## Scope and source API finding

Invalidate stale volatile `filesize` and `fileaddr` before a TFTP GET/RRQ can start. This work does not enable or test a real transfer.

In the pinned `u-boot/common/cmd_nvedit.c`, `_do_env_set()` returns `!hdelete_r(...)` for deletion. `setenv(name, NULL)` therefore returns zero for successful deletion and one when the variable is absent or deletion fails. The helper must call `getenv()` before deletion.

## Production behavior

- Production helper: `tftp_invalidate_get_metadata()`.
- Attempt `filesize` and `fileaddr` deletion independently; continue the second attempt even if the first fails.
- Re-read both names and fail closed unless both are absent.
- Call only in the GET branch of `TftpStart()`, before RRQ state/request setup.
- On failure, set `NETLOOP_FAIL` and return without sending RRQ.
- No `saveenv`; the helper changes only volatile environment state.
- PUT and `TftpStartServer()` Server/WRQ paths are untouched. The normal successful-transfer metadata publication path is not modified.
- The patch is a source delta generated by `git diff --binary`, not a hand-written unified diff.
