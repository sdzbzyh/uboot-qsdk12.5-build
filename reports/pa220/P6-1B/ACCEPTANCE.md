## Scope

P6-1B completes the GET receive lifecycle after P6-1A's stale metadata invalidation. It does not execute a real TFTP GET and does not authorize file transfer.

## Production behavior

- A full maximum-size reservation is checked before RRQ. The default maximum is 32 MiB and can be overridden by `CONFIG_PA220_TFTP_MAX_FILE_SIZE`.
- The complete reservation is validated through the existing P4-2 `octeon_load_range_check()`; it is not inferred from per-block checks.
- Each DATA block must have the exact next expected offset. The block length must fit in the remaining reservation.
- Received-byte commit repeats the bounds check before incrementing the total. P4-2 continues to check block index, wrap offset, address arithmetic and the per-block destination range before writing.
- With `CONFIG_TFTP_TSIZE`, the server's decimal tsize is parsed using bounded arithmetic. Empty, malformed and over-limit values are rejected. The original PUT-side tsize conversion/storage behavior is retained.
- The state machine distinguishes IDLE, ACTIVE, COMPLETE and FAILED. Completion requires the accumulated receive length, `NetBootFileXferSize` and non-zero advertised tsize to agree.
- Failure handling covers reservation failure, P6-1A metadata-gate failure, non-sequential/oversized/out-of-range DATA, destination write failure, timeout/restart, TFTP ERROR, ICMP port-unreachable, invalid first block, tsize/length mismatch and command-level interruption/abort.
- The GET-only `TftpGetAbort()` hook runs after `netboot_common(TFTPGET, ...)` returns, so Ctrl-C/NetLoop failure cannot leave the receive state ACTIVE.
- Failure clears partial `NetBootFileXferSize`, marks FAILED and re-invalidates volatile `filesize`/`fileaddr`. No `saveenv` is called.
- PUT and Server/WRQ do not enter the GET helpers; the PUT tsize parsing path remains the original path.
