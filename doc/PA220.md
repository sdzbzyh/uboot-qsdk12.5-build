# PA-220 (OCTEON) U-Boot 独立构建

## 为什么使用独立构建入口

PA-220 的 U-Boot 来自 `pa220-openwrt/u-boot`，使用 Cavium OCTEON SDK 的 MIPS64 工具链和 `octeon_pa220_config`。它与本仓库原有的 Qualcomm QSDK U-Boot 2016 构建流程不是同一个目标，也不是可以直接合并板级目录的关系。

因此，`build-pa220.sh` 只负责准备固定版本的 PA-220 源码、调用其原生构建脚本并收集产物；原有的 `build.sh`、`u-boot-2016/` 和 Qualcomm 设备构建逻辑保持独立。

## 源码版本

当前固定使用：

- 仓库：<https://github.com/sdzbzyh/pa220-openwrt>
- U-Boot 子目录：`u-boot/`
- Git commit：`801717ba6a8a59ed2cfd53bf3e1b19841fecd2e8`

首次运行时，脚本会将仓库稀疏克隆到 `external/pa220-openwrt`，只检出 `u-boot/`，并切换到上述固定 commit。该目录由根目录的 `.gitignore` 排除，不会把整套 PA-220 源码提交进 QSDK 构建仓库。

## 编译依赖

需要 Linux 构建环境，以及：

- `git`
- `make`
- `nproc`
- OCTEON SDK 工具链，包含 `bin/mips64-octeon-linux-gnu-gcc`

来源仓库中的 `u-boot/build.sh` 还会使用该源码树里的 `tools/hostcc-gnu89`。

## 编译方式

将工具链目录传给脚本（目录本身应包含 `bin/`）：

```sh
./build-pa220.sh /path/to/tools-gcc-4.7
```

也可以先设置环境变量：

```sh
export OCTEON_TOOLCHAIN_DIR=/path/to/tools-gcc-4.7
./build-pa220.sh
```

如果交叉编译器已经在 `PATH` 中，也可以不传工具链参数：

```sh
./build-pa220.sh
```

可通过 `./build-pa220.sh --help` 查看参数。已有本地源码检出时，可以设置 `PA220_UBOOT_DIR=/path/to/pa220-openwrt/u-boot`；脚本仍会校验它是否处于固定的源码 commit，避免不知情地编译其他版本。

默认生成文件：

```
bin/pa220/u-boot-octeon_pa220.bin
```

也可用 `PA220_OUTPUT_DIR` 指定其他输出目录。脚本只编译并复制产物，不执行刷写操作。


## 启动链与镜像格式（源码核对）

### 启动链角色

PA-220 专用 U-Boot 源码目录中的 \`PA220-README.txt\` 将其定义为 Cavium OCTEON SDK 5.1.0 U-Boot 2013.07 加 PA-220 板级移植，定位是 SPI 启动链的最终阶段（stage 3）。它由 Palo Alto 原厂 stage 1 / 1.5 / 2 加载；原厂 stage 2 已初始化 DRAM。自定义 U-Boot 不负责从冷启动状态重新初始化 DRAM。

这一点不仅是 README 的描述，也与代码吻合：

- \`include/configs/octeon_pa220.h\` 定义 \`CONFIG_NO_CLEAR_DDR=1\`。
- \`arch/mips/cpu/octeon/octeon_dram.c\` 的 RAM-resident 路径读取 \`dram_size_mbytes\`，使用已由外部启动阶段配置好的内存大小；后续的 \`octeon_clear_dram()\` 又受 \`CONFIG_NO_CLEAR_DDR\` 条件保护。
- PA-220 配置中的 \`dram_size_mbytes=8192\` 是默认值；源码注释说明原厂 stage 2 传入的值优先。

因此，不应把这个镜像称作可直接替代原厂前级启动代码的独立 Boot ROM / stage 1。

### 链接地址与 RAM 测试地址

\`board/octeon/pa220/config.mk\` 将 \`CONFIG_SYS_TEXT_BASE\` 设为 \`0xC0000000\`。生成镜像时，U-Boot Makefile 调用 \`tools/update_octeon_header\`，把此链接地址写入 OCTEON 镜像头。

这不等于要求 TFTP 把镜像加载到同一个地址。来源仓库的安装指南第 9 步明确采用：

- 原厂 U-Boot 的 TFTP 缓冲地址：\`0x81000000\`
- 先执行 \`inv_icache\`
- 再执行 \`go 0x81000000\`
- 看到自定义 U-Boot 的 \`pa-220#\` 提示符后，才算完成 RAM 启动测试

镜像头定义为版本 1.2；Cavium 头文件的版本说明将 1.2 描述为基于 TLB 的可重定位镜像。MIPS 构建配置也启用了 PIC/重定位所需设置。因此，\`0xC0000000\` 是链接/头部地址，\`0x81000000\` 是安装指南使用的实际 RAM 加载地址，两者用途不同。具体硬件测试仍须以本机串口输出为准。

### 镜像头

\`tools/update_octeon_header.c\` 对头结构大小有 192 字节的编译期断言。生成的二进制包含 Cavium bootloader header，含有 \`BOOT\` magic、头 CRC、数据 CRC、board type、镜像长度、MIPS 虚拟地址和 image type。

PA-220 的构建入口调用 \`make octeon_pa220_config\`，随后走 U-Boot 的标准 Octeon \`u-boot.bin\` 规则和 \`rename\` 规则，最终产物名为 \`u-boot-octeon_pa220.bin\`。构建时未向 header 工具传入 stage2 / stage1 等特殊参数；工具默认采用 \`BL_HEADER_IMAGE_NOR\`，其枚举值为 3。这与 PA220-README 对最终镜像头 image type 3 的说明一致。这里的 image type 3 是 Cavium 定义的 NOR 类镜像标记，不应误读为枚举中的 \`BL_HEADER_IMAGE_STAGE3\`（其值为 2）；镜像作为 stage 3 使用是它在 PA-220 启动链中的角色。

### 文档记录的 SPI 布局

来源仓库的 \`u-boot/PA220-README.txt\` 和 \`docs/INSTALLATION.md\` 记录了以下布局。它们是仓库作者针对 PA-220 的安装记录，不代替对每台实际设备的只读核验：

| 区域 | 文档记录的用途 |
|---|---|
| \`0x000000–0x07ffff\` | Palo Alto 原厂前级启动阶段 |
| \`0x100000\` | Palo Alto 原厂 U-Boot，作为回退保留 |
| \`0x250000–0x39bfff\` | PA-220 定制 U-Boot 镜像写入区 |
| \`0xe00000\` | 正常 SPI 芯片的主环境区 |
| \`0xe10000\` | 正常 SPI 芯片的冗余环境区 |

安装指南将正常 SPI 芯片描述为 16 MiB，并要求在执行任何写入前通过定制 U-Boot 的 \`cpld read d\` 确认 \`Reg d = 0x31\`。指南明确要求绝不写入 failsafe SPI 芯片，也不使用 \`cpld write\`。这些地址、芯片选择值和区域边界必须先与实际机器的只读信息及完整备份相互核对，不能单凭文档推定所有设备修订版都一致。

### 当前可确认与未确认的边界

**从源码和安装文档可以确认：** 该镜像按 stage 3 设计；原厂前级负责 DRAM 初始化；镜像带 Cavium bootloader header；链接地址为 \`0xC0000000\`；仓库提供了先从原厂 U-Boot 经 TFTP 加载到 RAM 再执行的测试流程；环境变量保存位置在正常 SPI 芯片。

**仅凭公开源码还不能独立确认：** 原厂闭源 stage 2 在所有 PA-220 硬件修订版上的精确搜索算法、实际 SPI 芯片当前选择状态、设备上现存镜像及环境区内容、以及本次新编译产物能否在用户的机器上成功运行。这些要靠只读设备信息、完整备份和 RAM 启动测试确认。

本项目当前阶段不会自动执行 SPI 写入，也不会执行 \`saveenv\`。下一阶段应先完成本地可重复编译，再进行只读信息收集和 RAM 启动验证。

## 重要的启动与写闪存风险

**编译成功不代表可以直接替换设备中的原厂 Bootloader。**

PA-220 的板级配置注释说明，这个 U-Boot 作为 SPI stage 3 使用时，是由 Palo Alto 的 stage 2 加载到已经初始化的 DRAM 中；配置还定义了 `CONFIG_NO_CLEAR_DDR`。因此它不是一个可以不经验证就独立初始化整机内存并替换前级启动代码的通用完整 Bootloader。

环境区的配置已经可以从多个来源交叉确认：`include/configs/octeon_pa220.h` 的顶部有一条过时注释称环境只在 RAM 中，但其后明确配置 `CONFIG_ENV_IS_IN_SPI_FLASH`、`CONFIG_ENV_OFFSET=0xe00000` 和冗余偏移 `0xe10000`；`u-boot/PA220-README.txt` 与安装指南也都说明 `saveenv` 会写入正常 SPI 芯片。因此，**`saveenv` 会写闪存**，不能在 RAM 测试阶段把它当作无副作用操作。

在确认设备上的 SPI 芯片选择、完整备份和实际分区布局之前：

- 不要执行 `saveenv`；
- 不要执行 `sf erase/write/update` 等 SPI 写操作；
- 不要把生成的 BIN 直接刷入设备；
- 不要将此产物当作已经完成硬件验证的替代 Bootloader。

当前阶段只完成独立构建接入；尚未在本次执行环境中使用 OCTEON SDK 工具链完成实际编译，也未进行设备启动或写闪存测试。
