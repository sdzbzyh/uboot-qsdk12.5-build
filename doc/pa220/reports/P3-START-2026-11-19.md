## 1. 本轮目标与安全边界

P3 目标是建立 PA-220 板级、内存、时钟、网络、存储、EEPROM、CPLD 的只读诊断基础，为后续网络/Web/RAM 接收阶段提供可靠运行时数据。

本轮仅增加并验证只读诊断，不执行：
- `saveenv`；
- EEPROM/TLV 写入；
- CPLD 寄存器写入；
- SPI NOR/eMMC/NAND/USB block 写入、擦除、分区或格式化；
- `bootloaderupdate`；
- named bootmem block 分配或释放。

## 2. 新增命令

正式补丁：`patches/pa220/0001-pa220-read-only-maintenance-command.patch`

新增 `pa220 memory`，显示：
- `loadaddr`；
- `octeon_reserved_mem_load_base`；
- `octeon_reserved_mem_load_size`；
- `__tmp_load` named-block descriptor 的 base/size。

实现调用 `cvmx_bootmem_find_named_block("__tmp_load")`。该 API 返回 static descriptor；代码在查询后立即复制 `base_addr` 和 `size` 到局部变量，不保留 descriptor 指针，不分配/释放 block，也不写 RAM。

### 4.1 `__tmp_load` 与 bootmem free-list 边界核算

实机输出：

```
__tmp_load: base=0x20000000 size=0x10000000
```

named/free block 的关键区间按半开区间核算如下：

| 区域 | 区间 | 计算/关系 |
|---|---|---|
| `__tmp_reserved_linux` | [0x00100000, 0x0F100000) | base 0x00100000 + size 0x0F000000 |
| free block 0 | [0x0F100000, 0x0FFF55A0) | 0x0F100000 + 0x00EF55A0 = 0x0FFF55A0 |
| `__mac_meminfo` | [0x0FFF55A0, 0x0FFF5BB0) | 紧接 free block 0 |
| `__int_4_link_info` | [0x0FFF5BB0, 0x0FFF5BC0) | 紧接 `__mac_meminfo` |
| `__int_1_link_info` | [0x0FFF5BC0, 0x0FFF5BE0) | 连续 |
| `__int_0_link_info` | [0x0FFF5BE0, 0x0FFF5C00) | 连续 |
| `__boot_vector1__` | [0x0FFF5C00, 0x0FFFDC00) | base 0x0FFF5C00 + size 0x8000 = 0x0FFFDC00 |
| `__tmp_load` | [0x20000000, 0x30000000) | base 0x20000000 + size 0x10000000 |
| free block 1 | [0x30000000, 0x20F000000) | 0x30000000 + 0x1DF000000 = 0x20F000000 |
| `__uboot_code_data` | [0x20F000000, 0x21F000000) | 紧接 free block 1，size 0x01000000 |

低地址固定保留项还包括：
- `__fdt`：[0x00080000, 0x000A0000)；
- `__low_reserved_000000000000_0`：[0x000A0000, 0x000FF000)；
- `__tmp_uboot_exception`：[0x000FF000, 0x000FF500)；
- `__low_reserved_000000000000_1`：[0x000FF500, 0x00100000)；
- `idle-core-loop`：[0x000FFFF0, 0x00100000)。

逐项核算后，free block 0 的终点正好等于 `__mac_meminfo` 起点；后续低地址 named blocks 连续排列。free block 1 的终点正好等于 `__uboot_code_data` 起点。`__tmp_load` 的终点正好等于 free block 1 的起点。当前输出没有显示这些已列区间相互重叠。

**注意：** 上述结论只针对本次 `namedprint/freeprint` 输出中列出的 bootmem descriptor 和 free-list 区间；它不是对所有物理地址 alias、TLB 映射或所有 DRAM 写入目标的通用安全证明。

## 5. 尚未收敛的观察项

1. `bdinfo memstart=0x80000000` 与 `loadaddr/__tmp_load base=0x20000000` 属于不同信息字段。当前能确认 loadaddr 与 named-block base 一致，但尚未完成 cached/uncached alias、物理地址和 Stage2 handoff 的完整映射证明。
2. `octeon_reserved_mem_load_base` 与 `octeon_reserved_mem_load_size` 未设置；当前 `pa220 memory` 通过 named-block API 仍成功读取 `__tmp_load`。
3. `Relocated: 0x0` 是先前 `pa220 status` 观察项，尚未解释；不影响当前只读命令成功，不作为本轮阻断项。
4. TLV EEPROM/I2C 的实际只读窗口和 tuple 内容尚未在本轮验证。
5. 网络、存储只读诊断仍需按 P3 范围继续补齐。

不得把以上未完成项描述为已通过。尤其在地址 alias/写入范围验证完成前，不开放任意地址 RAM 上传。

## 8. 地址区间算术勘误（2026-11-19 历史审计）

历史版本第 4.1 节将 `__boot_vector1__` 的区间终点写为 `0x10003C00`，与用户提供的 namedprint base/size 不符。用户原始条目为 base `0x0fff5c00`、size `0x00008000`；正确半开区间为 `[0x0FFF5C00, 0x0FFFDC00)`，因为 `0x0FFF5C00 + 0x8000 = 0x0FFFDC00`。本次只更正文档算术，不重新执行 namedprint 或任何硬件测试。其他相邻区间的边界关系仍按用户提供的 base/size 分别核算。
