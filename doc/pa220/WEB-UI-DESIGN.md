# PA-220 Web UI 设计目标

## 目标

PA-220 最终 Web 页面在视觉语言、导航结构和交互体验上应接近 uBootKit 的 Argon 风格界面，并针对桌面和移动设备适配。此要求是项目交付目标，不代表需要移植 uBootKit 的全部业务功能。

## 参考来源与版本说明

- 固定 uBootKit 评估基线：`chenxin527/uboot-qsdk12.5-build@9ce315735ac88fd0a7c7697bc527a8616ed0a972`。其项目 README 明确描述 Argon 风格及移动端优化。
- 相关上游页面实现可参考 `1980490718/u-boot-2016@1f0979a2f6871eeb93e191e1dc9052a222b83919` 下的 `failsafe/html/pig/index.html`、`style.css`、`term.html`、`about.html`。这是相关上游实现的视觉参考，不应未经核对就宣称与固定 uBootKit commit 的每个前端文件完全相同。
- 上游参考具有侧边导航、内容卡片、图标、标签页、主题切换、表格/表单、终端布局、移动端 viewport 适配和压缩静态资源构建流程。

## PA-220 应保留的视觉特征

1. 深色优先、低眩光背景，蓝色作为主要强调色；提供明暗主题切换。
2. 桌面端采用侧边导航 + 主内容区；窄屏改为适合触控的折叠/顶部导航。
3. 页面使用一致的卡片、标题、图标、标签页、表格、表单、按钮、提示和状态样式。
4. 重要状态（连接、设备信息、内存区间、接收进度/校验结果）清晰可读。
5. 表格在窄屏可横向滚动或转换为易读布局；按钮有明确禁用、忙碌、成功和失败状态。
6. 终端风格只作为视觉参考；不意味着 PA-220 第一版要提供命令终端。

## PA-220 功能边界

PA-220 的 UI 只能展示已经存在且经过验证的后端能力。不能因参考页面存在某个菜单就直接增加对应接口。

- 首版只读：板卡/版本、网络状态、内存与 named-block 信息、只读诊断。
- HTTP GET/HEAD 与只读 URI handler 继续作为已验证服务基础。
- 不移植任意 U-Boot 命令执行、webterm、环境变量修改/删除/重置、saveenv、重启、升级、刷写、分区备份写入、EEPROM/CPLD/flash 操作。
- P6 RAM-only 接收完成后，可评估单独的“接收/校验”页面；页面不得提供自动执行、安装或持久化写入。
- 所有可能改变设备状态的按钮必须由独立后端能力、输入验证、确认流程和测试覆盖支撑；未经单独审查的功能不显示为可操作入口。

## 实施顺序

1. 完成当前 P6 软件与必要实机验证，不让前端工作干扰接收安全门。
2. 盘点 PA-220 已有只读 API 的字段、错误状态和轮询成本。
3. 基于上述 API 建立静态资源/页面服务，先做只读仪表盘。
4. 再实现网络、内存、诊断等只读页面，统一主题和响应式布局。
5. 用桌面 Chrome/Edge 与移动端视口检查布局、键盘/触控、加载失败和弱网行为。
6. 对页面静态资源生成、压缩、嵌入和最终目标镜像大小建立可重复构建验证。
7. 任何上传、命令执行或持久化操作均另立项目阶段，不属于视觉移植的默认范围。

## 验收

- 桌面和移动端页面结构与 uBootKit 参考风格一致。
- 所有页面共用颜色、间距、字体、图标和组件规范。
- 不出现未经实现/验证的按钮或菜单。
- 只读页面与现有 PA-220 HTTP API 一一对应。
- 静态资源构建可复现，目标镜像能正常提供页面。
- Web UI 验收与 HTTP/TCP 协议栈验收分开记录。
